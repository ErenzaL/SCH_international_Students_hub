# Research workspace - multilingual RAG evaluation

Reproducible, **read-only** evaluation of the SCH International Student Hub assistant. Nothing here is deployed,
nothing writes to the production database, and no student conversations are exported. All questions are synthetic.

```
research/
  configs/     experiments.json (methods, parameters, datasets, models, prompt version) · answer_rubric_v1.md
  data/        dataset_statistics.json · chunk_metrics.csv · corpus_manifest.json
               benchmarks/  retrieval_pilot_v0.1.json (development) · retrieval_heldout_v0.2.json (held-out test)
               results/     retrieval_*.csv (+ .manifest.json) · answers_production_heldout_v0.2.jsonl · summaries
               review/      label_review_worksheet.csv · answer_annotation_template.csv
  figures/     PNG + SVG, written by the notebooks
  notebooks/   01-14 (committed without outputs; executed copies go to notebooks/_executed/, git-ignored)
  reports/     research_summary.md · abstract_draft.md · retrieval_results_table.csv · dataset_summary.csv
               pipeline_diagram_spec.md · notebook_validation.json
  scripts/     analysis.py (metrics, statistics, figure style) · build_notebooks.py · run_notebooks.py
               run_retrieval_eval.py · run_answer_eval.py · make_annotation_template.py
               build_reviewed_dataset.py · export_dataset.sh · corpus_manifest.py
  sql/         dataset_statistics.sql · chunk_metrics.sql (run with --read-only)
```

## Environment (CPU only)

```bash
python3.11 -m venv research/.venv
research/.venv/bin/pip install -r research/requirements.txt
research/.venv/bin/python -m ipykernel install --user --name sch-research --display-name "SCH research (Python 3.11)"
research/scripts/get_fonts.sh      # Noto Sans KR (OFL) so figures show Korean (한글) labels
```

Figures fall back to an installed Korean system font (Apple SD Gothic Neo, Malgun Gothic, NanumGothic, Noto Sans CJK
KR) if the downloaded font is missing; SVGs embed glyph outlines, so they display correctly in PowerPoint.

The evaluation *runners* (`run_retrieval_eval.py --target local`) import the backend and use the backend's own
virtualenv (`backend/.venv`, see the backend README). The notebooks only read files in `research/data`.

## Run the notebooks

- **VS Code**: open a notebook, choose the kernel "SCH research (Python 3.11)", then *Run All*.
- **JupyterLab**: `research/.venv/bin/pip install jupyterlab && research/.venv/bin/jupyter lab research/notebooks`,
  select the same kernel, *Kernel → Restart Kernel and Run All Cells*.
- **Headless validation** (every notebook top to bottom in a fresh kernel):
  `research/.venv/bin/python research/scripts/run_notebooks.py` → `reports/notebook_validation.json`.

Notebooks are generated by `scripts/build_notebooks.py`; edit that file, not the `.ipynb` files.

## Refresh the data (read-only)

```bash
research/scripts/export_dataset.sh                       # DB statistics, public corpus snapshot, manifest
supabase db query --remote --read-only -f research/sql/chunk_metrics.sql --output-format json   # see notebook 02
cd backend
.venv/bin/python ../research/scripts/run_retrieval_eval.py --target local      --dataset ../research/data/benchmarks/retrieval_heldout_v0.2.json --out ../research/data/results/retrieval_local_heldout_v0.2.csv
.venv/bin/python ../research/scripts/run_retrieval_eval.py --target production --methods B0,E1,E2 --dataset ../research/data/benchmarks/retrieval_heldout_v0.2.json --out ../research/data/results/retrieval_production_heldout_v0.2.csv
cd .. && python3 research/scripts/run_answer_eval.py --out research/data/results/answers_production_heldout_v0.2.jsonl
python3 research/scripts/make_annotation_template.py
```

Production runs are rate limited (search 30/min, anonymous chat 6/min and 40 AI answers/day per IP); the runners pace
themselves. Answer runs use the owner's Gemini quota.

## Milestone 5 (notebooks 09-14) and the reliability sprint

| Notebook | Question | Main inputs |
|---|---|---|
| 09 retrieval error analysis | why retrieval fails (taxonomy) | `data/results[/<snapshot>]/error_analysis_*.jsonl` |
| 10 multilingual reranking | do cross-encoder rerankers help, per language | `reranked_<model>_*.jsonl`, `experiments_*.csv` |
| 11 context selection | how the assistant's evidence selection changes the context | `context_*.csv` |
| 12 statistical comparison | paired bootstrap / McNemar / Holm across methods | `experiments_*.csv` |
| 13 Korean PDF chunk quality | the guidebook extraction defect and 6 chunking variants | `data/experiments/chunking/` |
| 14 retrieval reliability | failure audit, evidence-sufficiency layer, source quality | `data/experiments/reliability/` |

Snapshots: `RAG_SNAPSHOT=corpus_v1 | corpus_v2 | corpus_v2_p1` selects the corpus and the results folder
(`scripts/snapshot_paths.py`); `run_notebooks.py` defaults to `corpus_v2`. Final write-up:
`reports/milestone5_final_report.md`; corrections: `reports/ERRATA.md`.

Pipeline (each step reads the previous step's files):

```bash
cd backend   # the runners import the backend
RAG_SNAPSHOT=corpus_v2 .venv/bin/python ../research/scripts/make_candidates.py          # first-stage pools (B0F, E1, E2)
RAG_SNAPSHOT=corpus_v2 SNAPSHOTS=corpus_v2 ../research/scripts/rerank_all.sh            # rerankers (research/.venv-rerank)
RAG_SNAPSHOT=corpus_v2 .venv/bin/python ../research/scripts/assemble_experiments.py
RAG_SNAPSHOT=corpus_v2 .venv/bin/python ../research/scripts/run_error_analysis.py
.venv/bin/python ../research/scripts/pdf_chunk_variants.py && .venv/bin/python ../research/scripts/run_chunking_experiment.py
.venv/bin/python ../research/scripts/run_reliability_experiment.py
cd .. && research/.venv/bin/python research/scripts/build_notebooks.py && research/.venv/bin/python research/scripts/run_notebooks.py
```

Known nondeterminism: the local in-memory store breaks E1 ties by random chunk UUIDs, so rebuilding E1 candidates
changes E1 rankings slightly (see `reports/ERRATA.md`). The committed candidate files are the ones every reported
number was computed from; do not regenerate them to "refresh" a result.

## Large files and data that is not committed

- **Compressed intermediates.** Files above ~5 MB (first-stage candidate pools and reliability traces) are committed as
  `<name>.jsonl.gz`; scripts read either form (`scripts/jsonl_io.py`, a plain local copy wins).
  `data/LARGE_FILES.sha256` holds the checksums of the uncompressed files.
- **Not committed:** the corpus text snapshots (`backend/.eval-cache/`, re-export with `export_dataset.sh`), the
  original guidebook PDF (`data/raw_private/`, downloaded read-only from private storage; SHA-256 recorded in
  `data/experiments/chunking/variants.manifest.json`), the per-variant `corpus.json` files (rebuild with
  `pdf_chunk_variants.py`), executed notebooks (`notebooks/_executed/`) and the fonts.
- Notebooks 13 and 14 and the reliability runner import `backend/app/services/assistant/evidence.py` and
  `backend/app/services/source_quality.py`.

## Datasets and what may be claimed

| Version | Role | Review |
|---|---|---|
| retrieval-pilot-0.1 | development - used while tuning retrieval (results are optimistic) | AI-drafted, unreviewed |
| retrieval-heldout-0.2 | held-out test - frozen before its first evaluation, never used for tuning | AI-drafted, unreviewed |
| retrieval-reviewed-1.0 | independent test - built by `build_reviewed_dataset.py` from the filled review worksheet | human-reviewed (not yet created) |

Until `retrieval-reviewed-1.0` exists, every result is **preliminary**. Answer correctness, relevance and
faithfulness are **not evaluated** until reviewers score `review/answer_annotation_template.csv` with
`configs/answer_rubric_v1.md`; no simulated or model-invented scores are used. Do not tune retrieval on the held-out
or reviewed sets - create a new held-out version instead.
