# GPU worker (university server → Hub, outbound only)

Translation drafts and document summaries of **approved, public** content are generated by qwen2.5:7b-instruct on the
university GPU. The worker calls the Hub API over HTTPS. Nothing connects to the university server, Ollama stays on
127.0.0.1, and the live chatbot (Gemini) is not involved. Off by default (`GPU_WORKER_ENABLED=false`).

## What was reused, what is new

| Need | Reused | New |
|---|---|---|
| Durable jobs, retries, one open job per translation | `ingestion_jobs`, unique index, backoff, event log | `executor`, lease and cancel columns (migration 0016) |
| What to translate, versions, human work wins | checks of `AnnouncementAutoTranslator` / `DocumentTranslationService` | split into `prepare` / `store_result`, used by both executors |
| Prompts, quality checks, review, audit | `translation_drafts.py`, `quality.py`, review pages, `audit_log` | — |
| Finding missing languages | `translation/backfill.py` | admin endpoint `queue-missing` (dry run by default) |
| Model client | `OllamaProvider` (loopback only, no silent truncation) | one repair attempt per part |
| Login | none fits: user tokens are too powerful | worker credentials, usable on four endpoints only |

Not routed to the worker: student-written text, conversations, support requests, agent tasks (their results go to
students without review), discovery, chatbot. "AI summaries" are the existing reviewed summaries of long documents.

## Guarantees

| Requirement | How |
|---|---|
| Never published by the worker | results are always `needs_review`, even when every check passes (`machine_draft` can be public); approval needs a person |
| Only approved content leaves | the text must equal what the public site shows, before generating and before storing; the same rule applies to Gemini |
| Least privilege | claim, heartbeat, complete, fail; the token is rejected everywhere else and user tokens are rejected here |
| Credential | 256-bit random, SHA-256 stored, shown once, 90 days, rotation with optional overlap, pause, revoke |
| No production secrets at school | the worker needs only `httpx`; it refuses to start when Supabase or API-key variables are set |
| Lease, idempotency | the worker chooses the lease token: repeated claims and results change nothing; a late result is discarded |
| Source versions | a fingerprint of the sent text is compared before storing; changed → discarded and queued again |
| Human work | never replaced by a late result, also when "force" was requested before the edit |
| Offline | a lost lease (180 s) re-queues; 3 attempts; SIGTERM hands the job back without using one. Without a usable worker new requests use the server's own model; a job never waits longer than 48 hours |
| One job at a time | enforced in SQL across all workers and by a lock file on the server |
| Logs, metrics | ids, languages, codes, durations, token counts; failure reports are codes, metrics are numbers |

## Install on the university server

```bash
cd ~/projects/SCH_international_Students_hub/backend
uv venv --python 3.11 .venv-gpu
uv pip install --python .venv-gpu/bin/python -r requirements-gpu-worker.txt      # httpx only

mkdir -p -m 700 ~/.config/sch-gpu-worker
cp gpu-worker.env.example ~/.config/sch-gpu-worker/env && chmod 600 ~/.config/sch-gpu-worker/env
nano ~/.config/sch-gpu-worker/env                               # API URL, account name
(umask 077; read -rs -p 'Worker token: ' T; printf %s "$T" > ~/.config/sch-gpu-worker/token)

set -a; . ~/.config/sch-gpu-worker/env; set +a
.venv-gpu/bin/python -m app.gpu_worker --check                  # contacts Ollama only
```

## Run

```bash
.venv-gpu/bin/python -m app.gpu_worker --once      # at most one job
.venv-gpu/bin/python -m app.gpu_worker --drain     # until the queue is empty (recommended on free Render)
.venv-gpu/bin/python -m app.gpu_worker             # until stopped (Ctrl+C / SIGTERM hands the job back)
```

Continuous mode as a user service (`~/.config/systemd/user/sch-gpu-worker.service`; not installed automatically, ask the
administrators whether long-running user services are allowed):

```ini
[Service]
WorkingDirectory=%h/projects/SCH_international_Students_hub/backend
EnvironmentFile=%h/.config/sch-gpu-worker/env
ExecStart=%h/projects/SCH_international_Students_hub/backend/.venv-gpu/bin/python -m app.gpu_worker
Restart=on-failure
RestartSec=60
RestartPreventExitStatus=77 78
TimeoutStopSec=120
NoNewPrivileges=true
[Install]
WantedBy=default.target
```

Exit codes: 0 finished, 77 credential rejected, 78 configuration.

**Free Render hours.** An instance stays awake about 15 minutes after a request. Polling more often than that keeps the
API awake all month (about 744 of the 750 hours the pilot plan lists for the whole workspace). Two `--drain` runs a day
cost about 15 hours a month; hourly polling about 190; the default continuous mode backs off to one poll per hour.

## Administration

The calls below need `$API` (`https://<api host>/api/v1/admin/gpu`) and a super admin's `$ADMIN_TOKEN`
(`-H "Authorization: Bearer $ADMIN_TOKEN" -H 'content-type: application/json'` on each call, shown as `…`).

| Task | Call |
|---|---|
| Create a worker (token shown once) | `curl … -X POST $API/workers -d '{"name":"school-gpu"}'` |
| Rotate, old token valid 60 more minutes | `curl … -X POST $API/workers/ID/rotate -d '{"grace_minutes":60}'` |
| Rotate after a leak | `curl … -X POST $API/workers/ID/rotate -d '{}'` (the old token stops at once) |
| Pause / resume / revoke (final) | `curl … -X PATCH $API/workers/ID -d '{"status":"paused"}'` (`active`, `revoked`) |
| What is missing (dry run) | `curl … -X POST $API/jobs/queue-missing -d '{}'` |
| Queue 10 announcement translations | `curl … -X POST $API/jobs/queue-missing -d '{"dry_run":false,"limit":10}'` |
| Include documents / choose languages | `-d '{"dry_run":false,"kinds":["announcement","document"],"languages":["vi","id"]}'` |
| Cancel a job | `curl … -X POST $API/jobs/JOB/cancel` |
| Workers, queue, metrics | `curl … $API/status` |

After rotation write the new token to the token file; no restart is needed. The existing "Machine-translate" buttons also
queue to the worker while it is enabled. Reviewers see drafts under Admin → Translations → needs review.

Settings on Render: `GPU_WORKER_ENABLED`, `GPU_WORKER_JOB_TYPES` (`translate_announcement,translate_document`),
`GPU_WORKER_MODELS`, `GPU_WORKER_MAX_RUNNING` (1), `GPU_WORKER_LEASE_SECONDS` (180), `GPU_WORKER_JOB_MAX_SECONDS` (1800),
`GPU_WORKER_CHUNK_CHARS` (1200), `GPU_WORKER_ONLINE_HOURS` (24), `GPU_WORKER_MAX_QUEUE_HOURS` (48),
`GPU_WORKER_ON_EXPIRY` (`fail` or `local`), `GPU_WORKER_MAX_SOURCE_CHARS` (12000), `GPU_WORKER_TOKEN_DAYS` (90).

## Deployment checklist (nothing here has been done)

Status, blockers, approvals and the pilot: [release/gpu-worker-readiness.md](release/gpu-worker-readiness.md).

Before:
- [ ] University IT: may this account run an outbound worker that uses the GPU and contacts the Render host?
- [ ] Review and merge the branch; CI-equivalent tests green.
- [ ] **Manual `pg_dump`** of production (the pilot plan records that there are no automatic backups), stored off the
      university server.
- [ ] Confirm migrations 0001–0015 are applied. 0016 replaces `claim_ingestion_job`: apply it when no job is running.

Deploy, feature off:
- [ ] Apply `supabase/migrations/20261124000016_gpu_worker.sql`.
- [ ] Deploy the API with `GPU_WORKER_ENABLED` unset. Check `/health`, one chatbot answer (Gemini), one document upload,
      and that `/api/v1/gpu/claim` answers 404.
- [ ] Confirm `AGENT_SCHEDULES_ENABLED` and the `AUTO_TRANSLATE_*` settings have the values you want (off).

Enable:
- [ ] Set `GPU_WORKER_ENABLED=true`. Once a worker has contacted the API, requested translations wait for it instead of Gemini.
- [ ] Create the worker as super admin, save the token on the server, run `--check`.
- [ ] Dry run `queue-missing`, queue **one** announcement, run `--once`.
- [ ] Verify: status `needs_review`, not visible on the public page, a reviewer can edit and approve it.
- [ ] Pause, resume and cancel once. Rotate the token once.
- [ ] Queue in small batches; a native speaker checks the first drafts of every language.

Stop / roll back:
- [ ] Stop at once: revoke the worker, or set `GPU_WORKER_ENABLED=false` (chatbot and everything else unaffected).
      Open GPU jobs then fail visibly at the next sweep and can be requested again.
- [ ] Remove completely: `supabase/rollback/20261124000016_gpu_worker_down.sql` (drafts are kept).

## Limits

- Draft quality is that of a 7B model; the checks find lost facts, not wrong words. Every draft needs a person.
- The checks flag some correct drafts. Terms and names come from an unconfirmed list (`app/gpu_worker/glossary.py`).
- A job that was cancelled while running stops at the next heartbeat (up to 45 s).
- A compromised worker could hand in misleading drafts. They cannot become public without a reviewer.
- A result is stored in several database calls (as before). A crash in between leaves a draft whose job is queued again
  and then finishes without generating twice.
